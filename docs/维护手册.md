# 详细维护手册

本文对应当前目录结构。首次接触项目，先读“文件速查”和“page.tsx 的作用”，再按需要修改。新增一个完整栏目请读 [新增页面教程](新增页面教程.md)。

## 2. page.tsx 究竟干什么

`page.tsx` 是本项目采用的**命名约定**。这里使用 Vite 和 React Router，不是看到文件名叫 page 就自动创建路由。必须在 `src/App.tsx` 写 `<Route ... />`，页面才有 URL。

以手工为例：

```text
src/content/crafts/bottle-lamp.md
          ↓ crafts.data.ts 读取并调用 parseMarkdown
        crafts 数组
          ├─ page.tsx：列表，筛选、分页、卡片和空位
          ├─ detailpage.tsx：按 slug 找到一件作品，展示正文
          └─ home/sections/CraftPreview.tsx：首页选几件作品展示
```

手工 `page.tsx` 里有三个顶层函数：

1. `CraftsPage` 是整个列表页面。先读取 `crafts`，保存当前标签和页码，再筛选、分页、补空位，最后画出标题、按钮、卡片网格和分页器。
2. `CraftCard` 是一件作品的展示方式。调用 `useStand` 选工作台底图，处理作品图片是否加载成功，并绘制铭牌、蓝图摘要和开工/完工台历。点击卡片去详情页。
3. `EmptyCraftCard` 是没有作品的空格，负责空位底图和提示语，没有可进入的详情。

`useState` 保存用户操作后需要记住的状态。`items.filter(...)` 和 `slice(...)` 是根据状态计算结果，不需要再单独保存一份副本。JSX，也就是 `return (...)` 里的标签，定义界面结构；CSS 定义这些结构摆在哪里、长什么样。

**文件可以合并，函数不必塞成一个大函数。** 卡片函数写在文件顶层，既能保持阅读边界，也避免在每次列表重绘时重新定义组件。其他文件可以直接导入导出的卡片，例如首页文章区复用 `PostCard`。

普通列表的标签按钮已经放回各自 `page.tsx`。虽然结构相似，但分别保留后可以单独修改。博物馆使用 `category` 分类而非普通标签按钮，专属 `MuseumFilters.tsx` 留在博物馆目录。

首页 `home/page.tsx` 则是区域装配表，不承担普通列表功能。护照 `passport/page.tsx` 同时导出可嵌在首页和独立显示的组件，它们不需要人为加上不存在的详情页。

## 3. shared 三个文件的边界

| 文件        | 放什么                                                    | 何时需要修改                           |
| ----------- | --------------------------------------------------------- | -------------------------------------- |
| `config.ts` | 色板、颜色转换、栏目键、标题简介、每页数量                | 新增普通栏目、调整统一配置             |
| `data.ts`   | `sectionContent`、国旗 URL、各栏目文案配置汇总            | 新栏目加入首页汇总、搜索或公共缺图组件 |
| `utils.ts`  | 日期格式、图片地址解析、Markdown 解析、底图筛选与随机文案 | 改内容格式、日期规则或选择算法         |

这三个文件包含实际实现，不是把旧文件藏起来的转发入口。依赖方向是：`config → utils → 栏目数据/展示配置 → data → 页面与组件`。箭头表示后者可使用前者。不要让 `utils.ts` 再导入 `data.ts`，否则可能形成循环依赖。

`utils.ts` 的图片扫描已经覆盖整个 `src/content` 下的图片；新增栏目不需要再追加一串图片扫描路径。各栏目 Markdown 加载仍在自己的 `<栏目>.data.ts`，只加载直属 `.md`。

## 4. 添加内容与标签

复制 `src/content/<栏目>/_模板.md`，改成新的名字，例如 `wooden-shelf.md`。下划线开头的文件不会发布为内容。

普通内容示例：

```md
---
title: 我的木制小架子
date: 2026-09-04
finaldate:
tags:
  - 房间装饰
  - 木工
excerpt: 给房间做了一个放小物件的架子。
icon: 🪵
color: mint
previewImage: preview/wooden-shelf.png
detailImage: detail/wooden-shelf.jpg
---

## 材料

木板、砂纸和木蜡油。

## 制作过程

![打磨过程](images/sanding.jpg)
```

| 字段           | 用途和要求                                                                    |
| -------------- | ----------------------------------------------------------------------------- |
| 文件名         | 去掉 `.md` 后就是 slug，也是详情 URL 的最后一段；重命名会改变链接             |
| `title`        | 标题，留空时使用文件名                                                        |
| `date`         | 开始/发表日期，格式 `YYYY-MM-DD`；手工必须填，其他普通内容可用 finaldate 代替 |
| `finaldate`    | 结束/完成日期；注意全小写，手工据此判定“制作完成”                             |
| `tags`         | 标签列表，支持多行或 `[房间装饰, 木工]`；既生成筛选按钮，也参与底图规则       |
| `tag`          | 兼容旧单标签字段，会与 tags 合并，建议新内容统一用 tags                       |
| `excerpt`      | 必填摘要；列表卡片、搜索和详情简介都会使用                                    |
| `icon`         | 缺图图标；各栏目卡片不一定显示图标                                            |
| `color`        | mint、sunshine、sky、sun、rose、lavender，或十六进制色值                      |
| `previewImage` | 列表/首页封面；缺省时借用 detailImage                                         |
| `detailImage`  | 详情大图；缺省时借用 previewImage                                             |
| `readingTime`  | 可选分钟数，不填则按正文长度估算                                              |

普通解析器未填标签时会补栏目默认标签。它没有底图规则时仍按默认池选择，效果与无标签回退一致。标签文字需要一致；前后空格会去掉，但不同字、全半角差别或大小写不同仍是不同标签。`all` 是筛选的保留值，避免用作真实标签。

手工的“制作中”“制作完成”是状态筛选，依据 `finaldate` 自动计算。建议 Markdown 写“木工”“房间装饰”等内容标签，避免手工填写的状态与日期冲突。改变手工状态标签名称时，列表筛选和 `CraftCard` 传给 `useStand` 的状态文字要同时修改。

头部解析器是简单的键值解析，并非完整 YAML 引擎；摘要保持一行，不使用复杂对象或 `excerpt: |` 多行写法。正文则支持正常 Markdown。

### 博物馆的区别

博物馆使用 `museum.data.ts` 中的专属解析器。`id`、`category`、`excerpt` 必填，支持 `title`、`subtitle`、`year`、`date`、`rating`、图片和 tags。内置分类为 photos、games、books、music；自定义分类会自动出现，未配置中文名时直接显示原始值。

藏品详情 URL 是 `/#/museum/<category>/<slug>`，比普通栏目多一段分类。`category` 和 `tags` 都参与底图规则，而分类按钮只筛 `category`。

## 5. 图片放在哪里

```text
src/content/crafts/
├─ wooden-shelf.md
├─ preview/wooden-shelf.png  封面
├─ detail/wooden-shelf.jpg   详情大图
└─ images/sanding.jpg       正文过程照片
```

Markdown 中路径相对于**栏目目录**，如 `preview/wooden-shelf.png`，不是相对于整个项目。`public/images/...` 在浏览器中的地址从 `/images/...` 开始，不包含 public。外部 `https://...` 地址直接使用。

建议文件名保持简短稳定，中文和空格也支持。正文还兼容 `image/`、`images/` 查找与旧 `/src/collections/` 图片路径。封面展示会把 SVG 视作图标而非有效照片；需要真正的内容封面请用 PNG/JPG/WebP 等。

**图片文件后缀是 PNG，不等于有透明背景。** base.png、dark.png 已带透明通道，网页直接使用；替换素材时需导出带 Alpha 的 PNG。把棋盘格画进像素里的图片仍是不透明的。不要用 CSS 白色混合模式代替修改原图，否则作品里的白色也可能被影响。

## 6. 给其他 tags 添加随机图片集

### 6.1 默认目录

| 栏目          | `public/` 下的底图目录      |
| ------------- | --------------------------- |
| crafts 手工   | `images/crafts/workbenches` |
| museum 博物馆 | `images/museum/pedestals`   |
| recipes 菜谱  | `images/recipes/plates`     |
| planting 种植 | `images/planting/pots`      |
| travel 旅行   | `images/travel/postcards`   |
| posts 文章    | `images/posts/backgrounds`  |

默认池自动扫描本目录**直属图片文件**，支持 PNG、JPG/JPEG、WebP、AVIF、GIF、SVG，扩展名不区分大小写。不扫描其他栏目，也不递归扫描子目录。不存在或为空的目录回退到 CSS 外观。

开发时新增、删除和修改图片会触发更新；已经发布的网站必须重新构建发布。自动扫描配置在 `build/stand-assets.ts`，浏览器里没有读取硬盘目录的权限，实际是 Vite 在开发或构建阶段生成素材清单。

### 6.2 完整例子：房间装饰、木工、编织

先将 `wood-1.png`、`wood-2.png`、`weaving.png` 也放到手工 `workbenches` 目录。文件名是例子，请使用你真实添加的图片。

然后修改 `src/pages/crafts/presentation.data.ts`：

```ts
import standPools from 'virtual:island-stand-pools'
import { standPoolByFiles, type PresentationConfig } from '../../shared/utils'

// 全部底图来自手工文件夹；深色布局需要对应 CSS 配色。
const workbenches = standPools.crafts.map((stand) => ({
  ...stand,
  layout: stand.image.endsWith('/dark.png') ? 'dark' : 'default',
}))

export const presentation: PresentationConfig = {
  messages: {
    missing: ['正在制作中', '材料采购中', '灵感正在施工'],
    empty: ['等待新的手工作品', '工作台暂时空着'],
  },
  stands: {
    // 无标签规则命中时，在全部手工底图间随机。
    default: workbenches,
    byTags: [
      // 两个标签同时出现时优先用深色；特殊规则放前面。
      {
        tags: ['房间装饰', '木工'],
        match: 'all',
        pool: standPoolByFiles(workbenches, ['dark.png']),
      },
      {
        tags: ['房间装饰'],
        pool: standPoolByFiles(workbenches, ['base.png', 'dark.png']),
      },
      {
        tags: ['木工'],
        pool: standPoolByFiles(workbenches, ['wood-1.png', 'wood-2.png']),
      },
      {
        // 默认 any：编织或钩针任意一个标签出现就匹配。
        tags: ['编织', '钩针'],
        pool: standPoolByFiles(workbenches, ['weaving.png']),
      },
    ],
  },
}
```

这是**扩展示例**，当前实际配置仍只有你指定的“房间装饰 → base.png / dark.png”。示例第一条组合规则会让同时带“房间装饰、木工”的作品固定使用 dark.png；不需要这个特殊行为就不要加第一条。

`standPoolByFiles` 从已有素材池按文件名筛选，支持中文和空格，省去每条规则重复写 filter。传入哪个栏目的池，就只会从那个池找图片。

### 6.3 匹配顺序与回退

1. 普通卡片从上到下查 `byTags`，使用**第一条命中且图片池非空**的规则。
2. `match: 'any'` 为默认，命中一个标签即可；`match: 'all'` 要求该规则列出的标签全部存在。
3. 多条规则命中时不会合并图片池；优先级由数组先后决定。
4. 文件名不存在会被忽略。一条规则的所有文件都不存在时，继续查下一条规则；最后没有可用规则才回退 `default`。
5. 空位不匹配内容标签，优先 `stands.empty`，为空或未配置则用 `default`。
6. 一个池只有一张图就固定使用，多张图随机选择，允许不同卡片抽到同一张图。
7. `useStand` 为每次挂载保存一个随机种子。普通重绘不换图；刷新、路由重新进入或卡片重建时可能重抽。不是定时轮播，也不保证每次刷新都换另一张。

要限定空位，例如增加：

```ts
empty: standPoolByFiles(workbenches, ['base.png']),
```

写在 `stands` 中，和 `default`、`byTags` 同级。

### 6.4 “图片集”和物理子目录的区别

上面的 `pool` 是逻辑图片集。你不需要为每个标签新建文件夹，几条规则可以共用图片。

当前默认扫描明确只读直属文件，因此把图片放到 `workbenches/木工/` **不会自动进入池**。按当前实现维护，推荐同一栏目一个目录，用 `wood-`、`weaving-` 等文件名前缀区分，规则中选择对应文件。

也可按前缀自动组成一个逻辑池：

```ts
{
  tags: ['木工'],
  pool: workbenches.filter((stand) =>
    (stand.image.split('/').pop() ?? '').startsWith('wood-'),
  ),
},
```

如果将来确实要让物理子目录参与自动扫描，需要同时修改 `scanStandPools` 的递归范围、开发监听的路径判断和测试，并决定默认池是否包含子目录；只改一条文件路径还不够。本文没有偷偷改变当前“直属目录”的扫描规则。

### 6.5 其他栏目怎么写

以博物馆为例，在它的 `presentation.data.ts` 导入 `standPoolByFiles`，然后增加：

```ts
byTags: [
  {
    tags: ['games'], // category 也参与匹配
    pool: standPoolByFiles(standPools.museum, ['game-stand.png', 'museum-pedestal-v3.png']),
  },
],
```

新图片放 `public/images/museum/pedestals`。其余栏目换成相应的 `standPools.recipes`、`standPools.planting` 等即可。只改变池不会影响其他栏目。

底图规则作用于**调用本栏目 useStand 的卡片**。首页文章复用 PostCard，所以沿用文章卡片规则；首页手作展示板使用独立拍立得结构，不是手工列表工作台，不会因修改工作台池而自动变成列表工作台。

## 7. 底图与坐标如何配合

`standAttributes` 为卡片根元素写入 `data-stand-layout` 和 `--stand-image`。页面 CSS 再把它用于底图层。更换图片不能只看透明背景，还要看标题、照片和日期的留白位置是否一致。

手工常用选择器：

| 选择器                                     | 负责内容          |
| ------------------------------------------ | ----------------- |
| `.craft-workbench-card`                    | 单个工作台整体    |
| `.craft-workbench-base`                    | PNG 底图          |
| `.craft-art-frame`                         | 作品照片/缺图提示 |
| `.craft-nameplate`                         | 作品标题          |
| `.craft-blueprint-description`             | 蓝图上的摘要      |

### 音乐文件、内嵌封面和排序

音乐放到 `public/music/`，现在按 **`歌手 - 歌名.mp3`** 命名，例如：

```text
public/music/
├─ Linkin Park - One More Light.mp3
├─ Geoff Knorr - Elizabeth Peace - England.mp3
└─ covers/                              可选的手动封面
   └─ One More Light.jpg
```

- 只拆第一个 `-`，所以第二首的歌手是 `Geoff Knorr`，歌名是 `Elizabeth Peace - England`。没有带空格的分隔符时兼容第一个 `-`；没有任何分隔符时显示“未知歌手”。为避免歌手自身的连字符产生歧义，推荐统一使用带空格的格式。
- 支持 MP3、M4A、WAV、MP4、MPEG、AAC、OGG、FLAC，直接放到音乐目录第一层。重新构建后更新线上清单，开发时添加或删除文件会自动刷新。
- MP3/M4A 内嵌封面自动提取，不必手动导出。可选外部封面放 `public/music/covers/`，优先匹配完整音频文件名（不含扩展名），其次匹配完整歌名。外部封面覆盖内嵌封面；都没有时显示音乐图标。
- 扫描与封面提取在 `build/music-playlist.ts`，`vite.config.ts` 只负责注册插件。开发时打开播放器才读取当前封面；以文件名、大小和修改时间缓存读取结果。构建时输出到 `dist/assets/music-covers/`，相同内容只保存一次；不要手动维护这些生成文件。
- 修复了旧的封面字节处理：`Uint8Array.toString('base64')` 并不能可靠生成 Base64 图片。现在直接输出二进制图片，不再在首页 JavaScript 中内嵌全歌单封面。
- `MusicPlayer.tsx` 中的 `<audio preload="none">` 让刷新页面不预先请求音频，点击播放后才加载。封面只在面板展开时加载，歌单也不为每首歌额外请求缩略图。
- 拖动歌曲左侧六点手柄修改顺序，手机同样可拖；手柄外上下滑动歌单。右侧上下按钮保留给键盘和精确移动。拖动不会切换当前歌曲或重置进度，顺序保存到本机。
- 修改可见歌曲数量：`src/components/music-player/styles.css` 的 `.music-playlist`。目前行高 42px、间隔 3px、顶部留白 9px、边框 1px，五行总高度为 `5 × 42 + 4 × 3 + 9 + 1 = 232px`。超过五首时内部滚动；很矮的屏幕允许整个面板额外滚动。
- 右上角关闭叉已删除；再次点顶部音乐图标或点击面板外收起。音量、排序、禁用记录保存在 localStorage，只影响当前浏览器，不会更改磁盘音乐文件或其他访客的顺序。

### 天气、日期、日月和主题

顶部“天气与时间”打开岛屿气象室。日期可选 1900–2100 年，滑条覆盖 **00:00–24:00**，精度为一分钟。`24:00` 表示所选日结束的午夜，也就是次日 `00:00`，首页时钟及天文摘要显示这个实际时刻所在的日期。选择日期用于天空预览，天气仍沿用当前实况或你手动选的天气，不把当前天气误称为历史/未来的天气。

计算使用 [SunCalc 2](https://github.com/mourner/suncalc) 的日期、经纬度和天文算法。**2.x 的角度单位是度，方位角从北顺时针计算**，不要套用旧版弧度公式。日期按定位时区解释，也处理夏令时；不存在的小时向后顺延，重复小时取较早的一次。定位失败使用上海（31.23, 121.47，Asia/Shanghai），控制器明确写“上海（参考位置）”。接口最多等待 10 秒，不阻塞网站显示。

`calculateSky` 保留以下大阶段用于星星、地景等自然效果；界面颜色使用文末细分时间线：

1. 太阳高度 ≥ 6°：白天，薄荷蓝天空。
2. 太阳高度在 -6° 到 6°：按太阳正午区分晨曦与落日，暖橙色天空。
3. 太阳低于 -6°、但高于 -18°，或仍在日落后三小时内：蓝紫暮色。
4. 其他时刻：接近黑色的深夜。

天体的地平线判断使用太阳高度，全站界面明暗则使用下面的连续阶段色板。日期不同，日出日落不同，同一滑条时刻也可能出现不同主题。极昼/极夜没有日出日落时显示对应文字。月相按所选瞬间计算，月亮的升落位置独立于太阳；因此某些夜晚月亮还没升起，白天也可能看得到月亮。太阳与月亮在地平线以下隐藏，云、雾降低可见度，雨雪雷暴遮挡日月。坐标经过插画投影，适合视觉场景，不作为专业星图。

“实时时间”和“实时天气”分别重置各自覆盖；仅关闭面板不会重置。刷新恢复实时模式。天气覆盖不改变日期，修改日期也不会丢失天气选择。

## 11. 常见问题

- **Markdown 没显示**：检查文件是否以下划线开头、是否在栏目直属目录、头部 `---` 是否完整、必填日期和摘要是否存在。
- **标签没有出现**：标签按钮来自内容，不来自底图规则；只写 byTags 不会凭空创建内容标签。
- **某个标签用了意外底图**：查是否先命中了上面的规则，以及目标文件名是否存在。空池会继续匹配或回退默认池。
- **底图规则不影响首页手作板**：首页板与列表工作台是两个结构，修改 `home/sections/CraftPreview.tsx` 和对应首页 CSS。
- **文件改名后图片丢失**：同步改 Markdown 路径或 byTags 文件清单；默认池自动更新不代表手写规则也会自动改名。
- **新增 page.tsx 但打不开**：本项目没有文件自动路由，必须修改 App.tsx。
- **本地正常、线上没有新图**：确认素材已提交并重新构建发布，必要时刷新浏览器缓存。

### 连续主题色与全站渐变（2026-09-05 更新）

`shared/utils.ts` 的 `dailyPhases` 计算时间阶段，`scenePalette` 统一生成界面颜色。色调按阶段进度在深夜、暮蓝、暖橙晨昏与日光色板之间连续插值，`ThemeProvider` 一次更新根元素的颜色变量。`calculateSky` 的阶段名称只用于描述天空；不再让各页面用 `data-scene-period` 分别硬切背景。

- 修改天空、纸面、正文及浅强调色：编辑 `scenePalette` 的色标。晨曦与落日共用暖色组，太阳越过地平线不会突然把半个页面切黑。

- 配色变量包含纸面、正文、次要文字、强调文字与浅强调色；底图、照片、实体纸质护照等内容素材保留自身色彩。减少动态效果偏好会关闭根颜色动画。

### 晨昏过渡的可读性保护

深色文字和浅色文字不能直接与背景一起做 RGB 混色，否则两者在中间亮度可能几乎同色。`shared/utils.ts` 的 `readablePalette` 会：

1. 根据纸面亮度选择全站文字的统一深浅方向。
2. 轻微修正纸面、页面渐变两端和浅强调底色，给对比度留余量。
3. 尽量保留正文、次要文字、链接原有色相，不足时向黑或白靠拢，计算目标至少 4.5:1。
4. 为强调按钮提供配对的 `--on-accent`，避免浅按钮上继续显示白字。

这使用 [W3C 文字对比度公式](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)，保护范围是共享色板生成的文字与阅读表面，不表示照片、素材内文字或全站所有组件已经通过完整无障碍认证。

`ThemeContext.tsx` 用 requestAnimationFrame 在 800ms 内逐帧更新色调，每帧都运行保护算法。文字深浅方向切换时不做交叉淡化，这是有意避免灰字；天空及背景仍渐变。不要恢复根变量或组件颜色的二次 CSS 插值，它可能重新生成未经检查的低对比中间色。`data-palette-changing` 期间仅保留位移、透明度、阴影和滤镜等过渡，结束后恢复原组件交互。

验证：`node scripts/test-theme-contrast.mjs` 扫描全部色调、六类天气，以及 04:10–04:20、20:05–20:15 在多个季节的表现。颜色搭配变更后执行此脚本。

### 顶部栏恢复纯色（最新规则）

首页滚动不超过 90px 时顶部栏透明，向下超过 90px 后切为纯色绿色 `#39775e`；夜间使用纯色深绿 `#263f43`，搭配白色导航文字。其他页面始终使用纯色顶部栏，保持固定定位。即使地址保留首页锚点，回到顶部也恢复透明。

修改颜色：`src/components/header/styles.css` 的 `.inner-topbar` 与夜间规则。修改滚动阈值：`Header.tsx` 的 `window.scrollY > 90`。这条规则替代上文“顶部栏使用页面渐变”的旧说明；页面、天空和页脚仍使用原来的渐变体系。

### 顶部栏纯色随主题变化（替代固定绿色规则）

首页顶部仍透明，滚动超过 90px 或进入其他页面后显示纯色导航。颜色通过 `scenePalette` 每组 `colors` 的第十项控制：子夜深蓝黑 `#111925`、深夜蓝灰 `#202c40`、黎明前/入夜靛紫 `#4b4563`、黎明/薄暮玫瑰棕 `#895765`、日出/黄昏暖杏棕 `#99643d`、正午绿色 `#39775e`。相邻阶段按同一个色调进度平滑插值，始终是纯色而非渐变图。

CSS 使用 `--header-background` 和 `--header-ink`；纯色顶栏始终深底白字，全部中间色的文字对比度由 `test-theme-contrast.mjs` 检查。修改配色时同步运行该检查，避免重现晨昏文字看不清的问题。

### 首页日历与天气预报

- `src/pages/home/sections/Hero.tsx`：右上角整块天气卡的日历入口；时间上排左侧是阶段小字、右侧为大号时间，下排是日期与星期。星期与场景使用同一定位时区。
- `src/pages/home/sections/Calendar.tsx`：月份导航、日期选择、当天农历节日、未来 7 天预报及弹窗键盘交互。浏览日历不改变首页场景日期；每次打开回到场景所在月份，点击“回到今天”查看真实当地日期。
- `src/pages/home/styles/weather.css`：天气卡排版、日历尺寸、日期格和预报横向滚动样式。调整弹窗宽度修改 `.island-calendar`，调整日期格高度修改 `.calendar-grid button`。
- `src/shared/utils.ts` 中 `calendarDay`：使用浏览器内置中国历转换农历。`solar` 添加 `MM-DD: 节日名`，`lunar` 添加 `农历月份名称-日数: 节日名`（如 `'八月-15': '中秋节'`）。闰月不重复标节日，除夕根据次日是否正月初一判断。目前覆盖元旦、春节、元宵、劳动节、儿童节、端午、七夕、中秋、国庆、重阳、腊八、除夕；不包含节气计算和年度调休表，不把标记解释为放假安排。
- `src/hooks/useLocalWeather.ts`：原有 Open-Meteo 请求同时获取 daily 预报，日期数组与最低/最高温、天气代码、降水概率按索引对应。预报保存在共享天气状态中，打开日历、切月不会再次请求。缺失值显示“—”或“暂无”，预报范围外不推测天气。真实预报不受气象室的模拟天气影响。

月相盈亏由时刻决定，同一时刻不同地点基本一致；坐标影响月亮高度与方位。现有月面绘制未按观测者位置旋转亮区，属于示意图。

日历交互更新：日历现为天气卡下方的非模态浮层，外观沿用音乐播放器的半透明纸色、圆角和阴影。点击入口切换开关，点击外部或 Esc 收起；不遮罩页面、不锁定背景滚动。`Calendar.tsx` 使用 Portal 避免首屏裁切，并跟随入口定位。时间与日期两排文字间隔统一为 `weather.css` 中的 `gap: 6px`。
