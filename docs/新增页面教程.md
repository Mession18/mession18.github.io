# 新增页面教程：从零接入“摄影”栏目

本文基于当前项目，示例栏目键为 `photography`、显示名称为“摄影”。示例只放在教程中，不会自动给网站添加一个你没要求的栏目。照着创建对应文件即可。

完成第 1～6 步即可得到：

- `/#/photography` 摄影列表，有标签、分页和卡片。
- `/#/photography/seaside` 一篇摄影详情。
- 首页摄影预览与进入列表的链接。

第 7 步再接入全站配置、搜索、导航和随机底图。若只是新增一个“关于我”静态页面，可直接看文末简化流程。

## 1. 先决定栏目和内容结构

```text
src/content/photography/
├─ seaside.md
├─ _模板.md                  可选，下划线文件不会出现在网站
├─ preview/seaside.jpg       可选，必须使用真实存在的图片
└─ images/process.jpg        可选，正文图片
src/pages/photography/
├─ photography.data.ts       读取 Markdown 并排序
├─ page.tsx                  列表和卡片
├─ detailpage.tsx            单篇详情
├─ styles.css                本栏目样式
└─ presentation.data.ts      第 7 步需要随机底图时再添加
src/pages/home/sections/
└─ PhotographyPreview.tsx    首页小型入口
```

摄影记录适合现有 `Post` 模型，可以复用普通 Markdown 解析器。若新栏目需要完全不同字段，如藏品的 category、rating，应参考 `museum.data.ts` 自建类型与解析器，不要把所有特殊字段都强行加入 Post。

创建 `src/content/photography/seaside.md`：

```md
---
title: 海边的一束光
date: 2026-09-04
tags:
  - 风景
  - 海边
excerpt: 记录傍晚落在海面上的光。
icon: 📷
color: sky
---

## 拍摄地点

海边步道。

## 拍摄记录

写下构图、光线和当时的感受。
```

先不填图片也能打开页面。放入真实图片后再加 `previewImage: preview/seaside.jpg`，正文可以写 `![过程](images/process.jpg)`。图片路径相对于 `src/content/photography`。

## 2. 写内容加载文件

新建 `src/pages/photography/photography.data.ts`：

```ts
import { parseMarkdown, type Post } from '../../shared/utils'

// Vite 在开发/构建时加载摄影目录的 Markdown 原文。
const files = import.meta.glob('../../content/photography/*.md', {
  query: '?raw',
  import: 'default',
  eager: true,
}) as Record<string, string>

// 共用解析器负责字段校验、模板排除和图片路径，页面只拿最终数组。
export const photography = Object.entries(files)
  .map(([path, source]) => parseMarkdown(path, source, '摄影'))
  .filter((item): item is Post => item !== null)
  .sort((a, b) => b.publishedAt.localeCompare(a.publishedAt))
```

`eager: true` 表示直接得到内容。下划线模板返回 null，被 filter 去掉。日期使用 `YYYY-MM-DD`，字符串排序即可得到从新到旧的顺序。

`src/shared/utils.ts` 已扫描所有 `src/content` 图片，所以新栏目图片无需额外登记。不要把这个文件 import 回 utils，避免循环依赖。

## 3. 写列表页和卡片

新建 `src/pages/photography/page.tsx`：

```tsx
import { useState } from 'react'
import { Link } from 'react-router-dom'
import { IslandPagination } from '../../components/pagination/IslandPagination'
import { useImageSource } from '../../hooks/useImageSource'
import { getPostDisplayImage, type Post } from '../../shared/utils'
import { photography } from './photography.data'

// 页面级状态只保存用户选择；筛选结果和页数直接从数据计算。
export function PhotographyPage() {
  const [activeTag, setActiveTag] = useState('all')
  const [page, setPage] = useState(1)
  const pageSize = 9
  const tags = [...new Set(photography.flatMap((item) => item.tags))]
  const filtered =
    activeTag === 'all' ? photography : photography.filter((item) => item.tags.includes(activeTag))
  const total = Math.max(1, Math.ceil(filtered.length / pageSize))
  const visible = filtered.slice((page - 1) * pageSize, page * pageSize)

  return (
    <div className="photography-page page-surface">
      <header className="page-heading">
        <p className="eyebrow">ISLAND PHOTOGRAPHY</p>
        <h1>摄影</h1>
        <p>收藏光线，也收藏看见它的心情。</p>
      </header>

      {/* 本页自己的标签按钮；换筛选后回到第 1 页。 */}
      <div className="content-filters" aria-label="摄影标签">
        {['all', ...tags].map((tag) => (
          <button
            key={tag}
            type="button"
            className={activeTag === tag ? 'active' : ''}
            aria-pressed={activeTag === tag}
            onClick={() => {
              setActiveTag(tag)
              setPage(1)
            }}
          >
            {tag === 'all' ? '全部摄影' : tag}
          </button>
        ))}
      </div>

      <section className="posts-library" aria-label="摄影记录">
        <div className="photography-grid">
          {visible.map((item) => (
            <PhotographyCard key={item.slug} item={item} />
          ))}
        </div>
        {visible.length === 0 && <p>这一页还在等待第一张照片。</p>}
        <IslandPagination page={page} total={total} onChange={setPage} />
      </section>
    </div>
  )
}

// 卡片放在文件顶层，可由首页导入复用；不要定义在 PhotographyPage 函数内部。
export function PhotographyCard({ item }: { item: Post }) {
  const { image, onError } = useImageSource(getPostDisplayImage(item))
  return (
    <article className="photography-card">
      <Link to={`/photography/${encodeURIComponent(item.slug)}`}>
        <div className="photography-image">
          {image ? (
            <img src={image} alt={item.title} onError={onError} />
          ) : (
            <span>{item.icon}</span>
          )}
        </div>
        <h2>{item.title}</h2>
      </Link>
      <p>{item.excerpt}</p>
      <time dateTime={item.publishedAt}>{item.publishedAt}</time>
    </article>
  )
}
```

这里复用全站的标题、筛选和分页样式，但卡片使用 photography 前缀，避免修改摄影样式时影响手工或博物馆。

示例没有强行补九个展台空位。若希望像手工一样补齐，计算 `Math.max(0, pageSize - visible.length)`，在网格中追加相应数量的本页 `EmptyPhotographyCard`。空位没有详情 URL，不应伪造 slug。

## 4. 写详情页

新建 `src/pages/photography/detailpage.tsx`：

```tsx
import { Link, useParams } from 'react-router-dom'
import { MarkdownContent } from '../../components/markdown/MarkdownContent'
import { useImageSource } from '../../hooks/useImageSource'
import { getPostDetailImage } from '../../shared/utils'
import { photography } from './photography.data'

export function PhotographyDetailPage() {
  // 路由参数来自 App.tsx 的 :slug；React Router 会解码参数。
  const { slug } = useParams()
  const item = photography.find((entry) => entry.slug === slug)

  // Hook 必须在条件 return 之前调用，避免首次找不到内容时破坏调用顺序。
  const { image, onError } = useImageSource(item ? getPostDetailImage(item) : undefined)
  if (!item) {
    return (
      <div className="page-surface not-found">
        <h1>没有找到这篇摄影记录</h1>
        <Link to="/photography">返回全部摄影</Link>
      </div>
    )
  }

  return (
    <article className="photography-detail page-surface">
      <Link to="/photography">← 全部摄影</Link>
      <header className="page-heading">
        <h1>{item.title}</h1>
        <p>{item.excerpt}</p>
        <time dateTime={item.publishedAt}>{item.publishedAt}</time>
      </header>
      {image && (
        <img className="photography-cover" src={image} alt={item.title} onError={onError} />
      )}
      <div className="tutorial-content">
        <MarkdownContent sourceDir={item.sourceDir}>{item.content}</MarkdownContent>
      </div>
    </article>
  )
}
```

`sourceDir` 不能漏，它告诉正文渲染器到 photography 内容目录查找相对图片。缺图、内容不存在和内容为空应分别处理。详情页使用原始正文，不需要先把 Markdown 手工转 HTML。

## 7. 接入全站维护功能

### 7.1 导航与栏目配置

`src/components/header/Header.tsx` 的 `navItems` 追加：

```ts
{
  to: '/photography',
  section: 'photography',
  label: '摄影',
  match: (path: string) => path.startsWith('/photography'),
  icon: 'icon-camera',
},
```

还要把 photography 加入 `updateHeader` 遍历的首页 ID 数组，并按首页顺序排列，这样滚动到摄影区时能高亮。新首页区块的 `id` 必须相同。

如果希望摄影使用公共栏目标题、分页配置和全站搜索汇总，再完成：

1. `src/shared/config.ts` 的 `ContentSectionKey` 联合类型追加 `'photography'`。
2. `contentSectionInfo` 添加 `photography: { title: '摄影', eyebrow: 'ISLAND PHOTOGRAPHY', description: '收藏光线，也收藏看见它的心情。' }`。
3. `allItemsLabel` 的 labels 中添加 `photography: '全部摄影'`。
4. `src/shared/data.ts` 导入 `photography` 数据，并在 `sectionContent` 对象加入 photography。
5. 摄影列表可以把第 3 步写死的标题与 `pageSize` 改成 `contentSectionInfo.photography`、`displayPageSize`；这只是共享配置，路由仍在 App.tsx 注册。
6. `src/components/section-icon/SectionIcon.tsx` 的 icons 添加 `photography: { icon: 'icon-camera' }`，页面需要时用 `<SectionIcon section="photography" />`。

`search.data.ts` 会遍历 `sectionContent` 生成内容搜索条目，也遍历 `contentSectionInfo` 生成入口。摄影若要独立图标/配色，扩展其中 sectionEntries 的 icon/color 分支；未扩展时会沿用末尾的默认分支。搜索既要有入口，也要有具体文章。

### 7.2 接自动随机底图

创建 `public/images/photography/frames/`，把真实底图放进去。以下例子假设有 `white.png` 和 `black.png`。

在 `build/stand-assets.ts` 的 `standDirectories` 增加：

```ts
photography: 'images/photography/frames',
```

在 `src/vite-env.d.ts` 中 `virtual:island-stand-pools` 的栏目联合类型追加 `'photography'`。这是类型声明，不会自动创建目录，也不决定路由。

新建 `src/pages/photography/presentation.data.ts`：

```ts
import standPools from 'virtual:island-stand-pools'
import { standPoolByFiles, type PresentationConfig } from '../../shared/utils'

export const presentation: PresentationConfig = {
  messages: {
    missing: ['照片还在整理中'],
    empty: ['等待下一束光'],
  },
  stands: {
    default: standPools.photography,
    byTags: [
      {
        tags: ['夜景'],
        pool: standPoolByFiles(standPools.photography, ['black.png']),
      },
      {
        tags: ['风景'],
        pool: standPoolByFiles(standPools.photography, ['white.png', 'black.png']),
      },
    ],
  },
}
```

在摄影 `page.tsx` 增加以下导入（已有 shared/utils 导入时合成一条即可）：

```tsx
import { useStand } from '../../hooks/useStand'
import { standAttributes } from '../../shared/utils'
import { presentation } from './presentation.data'
```

在 `PhotographyCard` 顶部、return 之前增加：

```tsx
const stand = useStand(presentation, item.tags)
```

把卡片的 article 开头替换为：

```tsx
<article {...standAttributes(stand)} className="photography-card">
```

此时选图逻辑已接通，还必须让 CSS **使用**这个变量。在摄影 `styles.css` 增加：

```css
/* 示范把选中的图片铺在卡片背景；相框需要按真实图片另调照片位置。 */
.photography-card[data-stand-image] {
  background-image: var(--stand-image);
  background-size: 100% 100%;
  background-repeat: no-repeat;
}
```

如果是有专门照片开口的透明相框，建议用独立底图层而非整张背景拉伸，并根据素材坐标调整摄影图片的位置和尺寸。逻辑接入不等于新素材的布局自动适配。

因为首页示例复用了 `PhotographyCard`，随机底图会同步影响首页预览。如果你给首页另写了卡片，需要在那个组件里自行调用 useStand。

### 7.3 接入公共缺图文案（可选）

若需要用 `ContentMessageText` 替代示例中的图标：

1. `src/shared/data.ts` 导入 `presentation as photographyPresentation`，并在 `presentations` 中加入 `photography: photographyPresentation`。
2. `src/components/content-placeholder/ContentPlaceholder.tsx` 的 `PlaceholderSection` 类型加入 `'photography'`。
3. 摄影页面导入 `ContentMessageText`，缺图分支改为：

```tsx
<ContentMessageText section="photography" kind="missing" />
```

这三项是使用公共文案组件时需要的登记。仅自己在 JSX 写一句提示、不调用公共文案时，无需扩展它的类型。

### 7.4 空位随机底图（可选）

在本页顶层定义空位组件，调用 `useStand(presentation, [], true)`，再把 `standAttributes(stand)` 放到空位根元素。`true` 表示这是空位，会优先使用 `stands.empty`，不会匹配普通内容 tags。用 `ContentMessageText` 的 `kind="empty"` 显示空位提示。

## 8. 完成后怎样验证

执行：

```sh
npx tsc --noEmit
npm run lint
node scripts/test-presentation.mjs
node scripts/test-stand-pools.mjs

```

手动检查这些实际场景：

- 首页出现摄影区，入口能进入列表。
- 列表显示新内容，标签能筛选，换标签重置页码。
- 卡片能进入正确详情；不存在的 slug 显示返回入口。
- 封面和正文相对图片能显示；故意填一个不存在的封面仍有缺图状态。
- 如果加了底图规则，已配置标签、未配置标签、无内容空位都符合预期。
- 窄屏和夜间配色没有横向溢出，导航能显示新增入口。
- 生产构建成功后，新图与 Markdown 已提交；线上部署成功后再核对一次。

## 9. 如果只新增一个静态页面

例如“站点说明”，不需要 Markdown、筛选、随机底图或详情：

1. 新建 `src/pages/site-info/page.tsx`，导出 `SiteInfoPage`，return 中写标题和正文。
2. 需要独立外观就新建同目录 styles.css，并在全站样式入口导入。
3. `App.tsx` 导入组件，注册 `<Route path="/site-info" element={<SiteInfoPage />} />`。
4. 在导航或首页某处添加 `<Link to="/site-info">站点说明</Link>`。
5. 需要跨栏目动画时，更新 `getRouteSection`。

不用为了统一目录而给静态页面创建空的 data、presentation 和 detailpage 文件。首页、列表、详情承担不同职责，根据真实内容选择需要哪几种页面即可。
