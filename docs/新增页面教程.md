# 新增页面教程：从零接入“摄影”栏目

本文基于当前项目，示例栏目键为 `photography`、显示名称为“摄影”。示例只放在教程中，不会自动给网站添加一个你没要求的栏目。照着创建对应文件即可。

完成第 1～6 步即可得到：

- `/#/photography` 摄影列表，有标签、分页和卡片。
- `/#/photography/seaside` 一篇摄影详情。
- 首页摄影预览与进入列表的链接。

第 7 步再接入搜索、导航和随机底图。若只是新增一个“关于我”静态页面，可直接看文末简化流程。

## 1. 先决定栏目和内容结构

```text
src/content/photography/
├─ seaside.md
├─ _模板.md                  可选，下划线文件不会出现在网站
├─ preview/seaside.jpg       可选，必须使用真实存在的图片
└─ images/process.jpg        可选，正文图片
src/pages/photography/
├─ photography.data.ts       读取 Markdown 并排序
├─ page.tsx                  列表和卡片
├─ detailpage.tsx            单篇详情
├─ styles.css                本栏目样式
└─ presentation.data.ts      第 7 步需要随机底图时再添加
src/pages/home/sections/
└─ PhotographyPreview.tsx    首页小型入口
```

摄影记录适合现有 `Post` 模型，可以复用普通 Markdown 解析器。若新栏目需要完全不同字段，如藏品的 rating，应参考 `museum.data.ts` 自建类型与解析器，不要把所有特殊字段都强行加入 Post。

创建 `src/content/photography/seaside.md`：

```md
---
title: 海边的一束光
date: 2026-09-04
tags:
  - 风景
  - 海边
excerpt: 记录傍晚落在海面上的光。
icon: 📷
color: sky
---

## 拍摄地点

海边步道。

## 拍摄记录

写下构图、光线和当时的感受。
```

先不填图片也能打开页面。放入真实图片后再加 `previewImage: preview/seaside.jpg`，正文可以写 `![过程](images/process.jpg)`。图片路径相对于 `src/content/photography`。

## 2. 写内容加载文件

新建 `src/pages/photography/photography.data.ts`：

```ts
import { loadPosts } from '../../shared/markdown'

// Vite 在开发/构建时加载摄影目录的 Markdown 原文。
const files = import.meta.glob('../../content/photography/*.md', {
  query: '?raw',
  import: 'default',
  eager: true,
}) as Record<string, string>

// 共用解析器负责字段校验、模板排除和图片路径，页面只拿最终数组。
export const photography = loadPosts(files, '摄影')
```

`eager: true` 表示直接得到内容。`loadPosts` 统一解析文章、排除下划线或“模板.md”文件，并按 `YYYY-MM-DD` 日期从新到旧排序。

`src/shared/markdown.ts` 已扫描所有 `src/content` 图片，所以新栏目图片无需额外登记。基础解析模块不要反向导入摄影数据，避免循环依赖。

## 3. 写列表页和卡片

列表复用 `ContentListPage`，先登记它需要的栏目配置：

1. 在 `src/shared/config.ts` 的 `ContentSectionKey` 中追加 `'photography'`。
2. 在 `contentSectionInfo` 中添加 `photography: { title: '摄影', eyebrow: 'ISLAND PHOTOGRAPHY', description: '收藏光线，也收藏看见它的心情。' }`。
3. 在 `allItemsLabel` 的 labels 中添加 `photography: '全部摄影'`。
4. 在 `src/components/section-icon/SectionIcon.tsx` 的 icons 中添加 `photography: { icon: 'icon-camera' }`。

新建 `src/pages/photography/page.tsx`：

```tsx
import { Link } from 'react-router-dom'
import { ContentListPage } from '../../components/content-list/ContentListPage'
import { useImageSource } from '../../hooks/useImageSource'
import { getPostDisplayImage, type Post } from '../../shared/markdown'
import { photography } from './photography.data'

export function PhotographyPage() {
  return (
    <ContentListPage
      section="photography"
      items={photography}
      renderCard={(item) => <PhotographyCard key={item.slug} item={item} />}
      renderEmpty={(key) => <EmptyPhotographyCard key={key} />}
    />
  )
}

function EmptyPhotographyCard() {
  return (
    <article className="photography-card">
      <div className="photography-image">
        <span>📷</span>
      </div>
      <p>等待下一束光。</p>
    </article>
  )
}

// 卡片放在文件顶层，可由首页导入复用；不要定义在 PhotographyPage 函数内部。
export function PhotographyCard({ item }: { item: Post }) {
  const { image, onError } = useImageSource(getPostDisplayImage(item))
  return (
    <article className="photography-card">
      <Link to={`/photography/${encodeURIComponent(item.slug)}`}>
        <div className="photography-image">
          {image ? (
            <img src={image} alt={item.title} onError={onError} />
          ) : (
            <span>{item.icon}</span>
          )}
        </div>
        <h2>{item.title}</h2>
      </Link>
      <p>{item.excerpt}</p>
      <time dateTime={item.publishedAt}>{item.publishedAt}</time>
    </article>
  )
}
```

`ContentListPage` 负责标题、标签筛选、每页数量、补空位与分页；栏目文件只提供内容和卡片。卡片使用 photography 前缀，避免修改摄影样式时影响手工或博物馆。

展台数量使用 `config.ts` 的 `displayPageSize`，当前每页九格；`renderEmpty` 为不足的格子提供占位。空位没有详情 URL，不应伪造 slug。手工状态标签、旅行省份筛选等额外规则可通过共享组件的回调配置。

## 4. 写详情页

新建 `src/pages/photography/detailpage.tsx`：

```tsx
import { useParams } from 'react-router-dom'
import { PostDetail } from '../../components/post-detail/PostDetail'
import { photography } from './photography.data'

export function PhotographyDetailPage() {
  const { slug } = useParams()
  return (
    <PostDetail
      item={photography.find((item) => item.slug === slug)}
      basePath="/photography"
      returnLabel="全部摄影"
      notFound={{ icon: '📷', title: '没有找到这篇摄影记录' }}
    />
  )
}
```

`PostDetail` 负责标题、日期、阅读时间、封面回退、正文和找不到内容的提示，默认使用文章布局；左右图文的教程布局可传 `layout="tutorial"`。栏目详情只负责按 slug 查询内容和传入文案。

正文通过 `item.sourceDir` 查找相对图片，`PostDetail` 已将它传给 `MarkdownContent`。直接传入原始 Markdown，不需要手工转 HTML。

在 `src/styles/index.css` 末尾追加：

```css

```

在 `src/App.tsx` 顶部加入导入：

```tsx
import { PhotographyPage } from './pages/photography/page'
import { PhotographyDetailPage } from './pages/photography/detailpage'
```

在已有 `<Routes>` 内、兜底 `path="*"` 附近加入两个同级 Route：

目前实际项目的详情页使用 `lazy(() => import(...))` 按需加载，外层已有 `Suspense`。上面的静态导入示例仍可运行；正式栏目可参照 `App.tsx` 中其他详情页改为 lazy，避免把正文渲染依赖提前放进首页。

```tsx
<Route path="/photography" element={<PhotographyPage />} />
<Route path="/photography/:slug" element={<PhotographyDetailPage />} />
```

再把 `'photography'` 加进 `getRouteSection` 的栏目数组。否则页面虽然能打开，跨栏目的过场动画仍可能把它当作 home。

此时启动开发服务器，先验证 `/#/photography`、`/#/photography/seaside` 和一个不存在的 slug。

## 6. 写首页预览区

新建 `src/pages/home/sections/PhotographyPreview.tsx`：

```tsx
import { Link } from 'react-router-dom'
import { PhotographyCard } from '../../photography/page'
import { photography } from '../../photography/photography.data'

// 首页展示最新三篇；复用卡片使封面和详情地址规则保持一致。
export function PhotographyHomeSection() {
  return (
    <section className="section home-photography" id="photography">
      <div className="section-heading">
        <h2>岛上的光影</h2>
        <Link to="/photography">全部摄影 →</Link>
      </div>
      <div className="photography-grid">
        {photography.slice(0, 3).map((item) => (
          <PhotographyCard key={item.slug} item={item} />
        ))}
      </div>
      {photography.length === 0 && <p>第一张照片正在路上。</p>}
    </section>
  )
}
```

在 `src/pages/home/page.tsx` 导入它：

```tsx
import { PhotographyHomeSection } from './sections/PhotographyPreview'
```

然后在希望的位置加入 `<PhotographyHomeSection />`。例如放在 `<CraftHomeSection />` 后，就是首页手作区的下一块。

首页可以复用列表卡片，也可以像现有手作板一样另写首页专属结构。若要不同外观，保留同一份 photography 数据，单独写首页 JSX 和 `home/styles/photography.css`，再由 `home/styles.css` 导入。不要复制两套内容数组。

## 7. 接入全站维护功能

### 7.1 导航与搜索

`src/components/header/Header.tsx` 的 `navItems` 追加：

```ts
{
  to: '/photography',
  section: 'photography',
  label: '摄影',
  match: (path: string) => path.startsWith('/photography'),
  icon: 'icon-camera',
},
```

还要把 photography 加入 `updateHeader` 遍历的首页 ID 数组，并按首页顺序排列，这样滚动到摄影区时能高亮。新首页区块的 `id` 必须相同。

第 3 步已经登记标题、分页和图标。现在在 `src/shared/data.ts` 导入 `photography` 数据，并在 `sectionContent` 对象加入 photography，让全站搜索收录具体文章。配置从 `shared/config.ts` 导入，国旗从 `shared/country-flags.ts` 导入，`shared/data.ts` 不作为转发入口。

`search.data.ts` 会遍历 `sectionContent` 生成内容搜索条目，也遍历 `contentSectionInfo` 生成入口。摄影若要独立图标/配色，扩展其中 sectionEntries 的 icon/color 分支；未扩展时会沿用末尾的默认分支。搜索既要有入口，也要有具体文章。

### 7.2 接自动随机底图

创建 `public/images/photography/frames/`，把真实底图放进去。以下例子假设有 `white.png` 和 `black.png`。

在 `build/stand-assets.ts` 的 `standDirectories` 增加：

```ts
photography: 'images/photography/frames',
```

在 `src/vite-env.d.ts` 中 `virtual:island-stand-pools` 的栏目联合类型追加 `'photography'`。这是类型声明，不会自动创建目录，也不决定路由。

新建 `src/pages/photography/presentation.data.ts`：

```ts
import standPools from 'virtual:island-stand-pools'
import { standPoolByFiles, type PresentationConfig } from '../../shared/presentation'

export const presentation: PresentationConfig = {
  messages: {
    missing: ['照片还在整理中'],
    empty: ['等待下一束光'],
  },
  stands: {
    default: standPools.photography,
    byTags: [
      {
        tags: ['夜景'],
        pool: standPoolByFiles(standPools.photography, ['black.png']),
      },
      {
        tags: ['风景'],
        pool: standPoolByFiles(standPools.photography, ['white.png', 'black.png']),
      },
    ],
  },
}
```

在摄影 `page.tsx` 增加以下导入；底图函数来自 `shared/presentation`，与内容解析的 `shared/markdown` 分开：

```tsx
import { useStand } from '../../hooks/useStand'
import { standAttributes } from '../../shared/presentation'
import { presentation } from './presentation.data'
```

在 `PhotographyCard` 顶部、return 之前增加：

```tsx
const stand = useStand(presentation, item.tags)
```

把卡片的 article 开头替换为：

```tsx
<article {...standAttributes(stand)} className="photography-card">
```

此时选图逻辑已接通，还必须让 CSS **使用**这个变量。在摄影 `styles.css` 增加：

```css
/* 示范把选中的图片铺在卡片背景；相框需要按真实图片另调照片位置。 */
.photography-card[data-stand-image] {
  background-image: var(--stand-image);
  background-size: 100% 100%;
  background-repeat: no-repeat;
}
```

如果是有专门照片开口的透明相框，建议用独立底图层而非整张背景拉伸，并根据素材坐标调整摄影图片的位置和尺寸。逻辑接入不等于新素材的布局自动适配。

因为首页示例复用了 `PhotographyCard`，随机底图会同步影响首页预览。如果你给首页另写了卡片，需要在那个组件里自行调用 useStand。

### 7.3 接入公共缺图文案（可选）

若需要用 `ContentMessageText` 替代示例中的图标：

1. `src/shared/data.ts` 导入 `presentation as photographyPresentation`，并在 `presentations` 中加入 `photography: photographyPresentation`。
2. `src/components/content-placeholder/ContentPlaceholder.tsx` 的 `PlaceholderSection` 类型加入 `'photography'`。
3. 摄影页面导入 `ContentMessageText`，缺图分支改为：

```tsx
<ContentMessageText section="photography" kind="missing" />
```

这三项是使用公共文案组件时需要的登记。仅自己在 JSX 写一句提示、不调用公共文案时，无需扩展它的类型。

### 7.4 空位随机底图（可选）

在第 3 步的 `EmptyPhotographyCard` 顶部调用 `useStand(presentation, [], true)`，再把 `standAttributes(stand)` 放到空位根元素。`true` 表示这是空位，会优先使用 `stands.empty`，不会匹配普通内容 tags。用 `ContentMessageText` 的 `kind="empty"` 显示空位提示。

## 8. 完成后怎样验证

执行：

```sh
pnpm check
```

`pnpm check` 包含类型检查、ESLint、六组脚本测试和生产构建。需要单独排查时使用 `pnpm typecheck`、`pnpm test` 或 `pnpm build`。

手动检查这些实际场景：

- 首页出现摄影区，入口能进入列表。
- 列表显示新内容，标签能筛选，换标签重置页码。
- 卡片能进入正确详情；不存在的 slug 显示返回入口。
- 封面和正文相对图片能显示；故意填一个不存在的封面仍有缺图状态。
- 如果加了底图规则，已配置标签、未配置标签、无内容空位都符合预期。
- 窄屏和夜间配色没有横向溢出，导航能显示新增入口。
- 生产构建成功后，新图与 Markdown 已提交；线上部署成功后再核对一次。

## 9. 如果只新增一个静态页面

例如“站点说明”，不需要 Markdown、筛选、随机底图或详情：

1. 新建 `src/pages/site-info/page.tsx`，导出 `SiteInfoPage`，return 中写标题和正文。
2. 需要独立外观就新建同目录 styles.css，并在全站样式入口导入。
3. `App.tsx` 导入组件，注册 `<Route path="/site-info" element={<SiteInfoPage />} />`。
4. 在导航或首页某处添加 `<Link to="/site-info">站点说明</Link>`。
5. 需要跨栏目动画时，更新 `getRouteSection`。

不用为了统一目录而给静态页面创建空的 data、presentation 和 detailpage 文件。首页、列表、详情承担不同职责，根据真实内容选择需要哪几种页面即可。
